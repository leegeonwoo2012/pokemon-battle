# ARENA / BATTLE LAB

React + TypeScript + Vite로 만든 비공식 포켓몬 배틀 게임입니다. CPU 싱글·더블과 친구 친선 싱글·더블을 지원합니다. 로컬에서는 같은 Wi‑Fi에서, Vercel 프런트엔드와 Render 릴레이가 배포되어 있으면 인터넷에서도 대전할 수 있습니다.

## 실행

Node.js 22.12 이상 또는 24 이상이 필요합니다. 프로젝트 폴더에서 다음을 실행하세요.

```powershell
npm ci
npm.cmd run dev
```

CMD에서는 `npm run dev`도 됩니다. 표시되는 `http://localhost:5173/`은 본인 PC용입니다. 친구는 실행 화면에 나오는 **Wi‑Fi IPv4 주소**의 `:5173/` 링크를 사용합니다. Wi‑Fi가 바뀌면 주소도 바뀝니다. 친구 대전 릴레이는 같은 명령으로 시작하며 8787 포트를 사용합니다. 다른 서버가 포트를 점유하면 기존 프로세스를 종료한 뒤 다시 실행해야 합니다.

## 이미 만든 웹사이트에 변경 사항 반영

이 폴더는 GitHub `leegeonwoo2012/pokemon-battle`의 `main` 브랜치에 연결되어 있습니다. 이 프로젝트에서 사용한 **Vercel 프런트엔드와 Render 친구 대전 서버가 둘 다 같은 GitHub 브랜치를 자동 배포하도록 설정되어 있다면**, 아래 명령으로 업데이트할 수 있습니다.

```powershell
cd "C:\Users\user\Documents\Codex\2026-10-09\pok-mon-champions-1-pok-mon"
npm.cmd test
npm.cmd run test:server
npm.cmd run build
git add src scripts package.json README.md
git commit -m "Add team preview and critical hit effects"
git push origin main
```

그다음 Vercel 프로젝트 **Deployments**와 Render 서비스 **Deploys**에서 새 커밋의 배포 완료를 각각 확인하고 기존 주소 `https://pokemon-battle-liard.vercel.app/`을 새로고침하세요. Render는 `npm run friend-server`를 실행하고 공개 포트는 `PORT` 또는 `FRIEND_PORT` 환경변수로 받습니다. Vercel의 **Production** 환경변수 `VITE_FRIEND_SOCKET_URL`은 `wss://pokemon-battle-miex.onrender.com/friend`를 가리켜야 합니다. Vite 환경변수는 빌드 시 반영되므로 값을 바꿨다면 Vercel을 다시 배포해야 합니다. 자동 배포가 꺼져 있다면 각 서비스 대시보드에서 해당 커밋을 수동 배포하세요. 서버 재배포 중 진행 중인 방은 메모리에서 사라지므로, 접속자가 없는 때에 배포하는 편이 좋습니다. [Vercel Git 배포](https://vercel.com/docs/git), [Render 자동 배포](https://render.com/docs/deploys).

## 현재 편성 목록

- Pokémon Showdown의 Champions **Regulation M‑C** 데이터 [고정 커밋 `942cda71`](https://github.com/smogon/pokemon-showdown/tree/942cda71d14bf0618bd57991708a2e2734b6daba/data/mods/champions)에서 팀 선택 가능 **264개 종·폼**을 추렸습니다. 기본형 230개와 지역·성별·크기·깃털 색에 따라 배틀 데이터가 달라지는 폼 34개입니다. 암컷 냐오닉스는 기본형의 허용 여부를 물려받으며 특성과 메가폼이 달라 별도 항목입니다. 펌킨인 크기별 종족값과 시비꼬 깃털별 특성도 따로 반영했습니다. 메가폼과 날씨·자세·외형만 바뀌는 폼은 팀 슬롯 수에 넣지 않았습니다. ID 전체와 선택 기준은 [`docs/regulation-m-c.json`](docs/regulation-m-c.json)에 있습니다.
- [공식 M‑C 안내](https://www.pokemon.com/uk/news/get-ready-for-regulation-set-m-c-in-pokemon-champions)는 허용 포켓몬 전체 목록을 게임 안에서 확인하도록 안내합니다. 따라서 264개는 공식 목록을 직접 추출한 숫자가 아니라 위의 Pokémon Showdown 고정 데이터에서 정한 팀 선택 폼 수입니다.
- 종족값·타입·가능한 특성·지원 기술의 학습 여부를 원본과 대조해 생성합니다. [`docs/roster-evidence.json`](docs/roster-evidence.json)에 종별 근거가 있습니다. 한국어 이름은 PokeAPI 이름 표를 사용합니다. 기존 로스터 132개 추가 항목은 이전 저장 팀과 엔진 회귀 테스트용 내부 데이터로 유지되지만 새 팀 선택 목록에는 보이지 않습니다.
- M‑C 학습 목록에 있는 **510개 기술**을 이름·타입·위력·명중률·PP·우선도 및 식별 가능한 기술 효과와 함께 편성 메뉴에 연결했습니다. 전용기도 이 목록에서 실제로 배울 수 있는 포켓몬에게 표시됩니다. 다단 공격, 랭크 변화, 상태, 날씨·필드, 설치물, 회복, 반동, 강제 교체, 급소·일격 효과를 자료에서 생성합니다. 다만 모든 기술의 특수 판정과 세대별 예외가 공식 엔진과 완전히 같지는 않습니다.
- 편성 화면에서 검색·타입 필터·6마리 팀·기술·특성·도구·성격·성별·IV·EV를 조정하고 저장·불러올 수 있습니다. 테라 타입은 원하는 타입의 **테라크리스탈 도구**를 장착해 정하며, 배틀 도중 다른 타입으로 바꿀 수 없습니다. 메타몽만 변신 1개 기술을 갖습니다. 새 편성 목록의 각 포켓몬은 최소 4개(메타몽 제외)의 지원 기술을 가집니다.

새 기본 파티는 **워시로토무 → 오롱털 → 한카리아스 → 리자몽 → 타부자고 → 대쓰여너**입니다. 이미 저장한 팀은 자동으로 덮어쓰지 않습니다. 편성 화면의 **새 기본 파티** 버튼으로 불러온 뒤 **팀 저장**을 누르면 교체됩니다. 파티 슬롯의 위·아래 화살표로 순서를 바꿔도 기술·특성·도구·성격·노력치 설정이 함께 이동합니다. 기술 선택 목록과 배틀 기술 메뉴는 한국어 이름순입니다.

## 배틀 규칙과 범위

### 팀 프리뷰와 선출

배틀을 누르면 양쪽 6마리 엔트리를 마주 보고 **싱글 3마리 / 더블 4마리**를 출전 순서대로 고릅니다. 포켓몬을 클릭하거나 순서 슬롯으로 끌어 배치할 수 있습니다. 친구 친선전에서는 서버가 90초 타이머와 양쪽 확정 상태를 관리하며, 미제출자는 시간 종료 시 팀의 앞 3마리 또는 4마리가 자동 선출됩니다. 상대 프리뷰에는 종·폼·레벨·설정된 성별만 보내고, 기술·도구·특성은 숨깁니다. 두 사람이 선출한 뒤 서버가 파티 순서를 확정하고 기존 배틀 엔진을 시작합니다. CPU 배틀도 같은 프리뷰 화면을 사용하며, 6마리 미만의 저장 팀은 기존 편성 기능과의 호환을 위해 현재 가진 포켓몬 수만큼 고를 수 있습니다.

### 급소와 타입 상성 연출

실제 피해 이벤트에 담긴 급소·타입 상성 결과로 피격 순간의 카메라 흔들림, 금색/붉은색/푸른색 섬광, 대상 근처 팝업과 합성 타격음을 결정합니다. **급소 + 약점**이면 두 팝업과 강한 흔들림을 함께 표시합니다. 이 효과는 HP 바가 줄어들기 직전 시작하며 무효 또는 회복 이벤트에는 표시하지 않습니다. 모션 줄이기 설정에서는 시각적 움직임을 생략하고 전투 메시지를 유지합니다.

자체 TypeScript 전투 엔진이 HP·타입 상성·자속·우선도·스피드·명중·급소·PP·상태·교체·승패를 계산합니다. 날씨·필드·설치물·장막·트릭룸·순풍·대타출동·중력·강제 교체·지연 공격·일격기와 일부 특성/도구를 지원합니다. 난수 시드를 지정하면 같은 행동의 결과가 재현됩니다. 서버가 친구 대전 판정을 계산하고 각 브라우저는 실제 이벤트를 순서대로 재생합니다.

반사기(카운터·미러코트), 죽기살기, 10종 충전기와 충전 중 잠수·비행 판정, 비에서 즉시 발사되는 일렉트로빔과 특수공격 상승, 볼트체인지를 포함한 교체기, 성묘의 아군 기절 수에 따른 위력, 해수스파우팅·분화의 남은 HP 위력, 철제광선의 HP 비용, 자폭류의 사용자 기절을 처리합니다. 잠자기·하품·아쿠아링·동료만들기·성별에 따른 헤롱헤롱, 역린의 기술 고정과 혼란, 스케일샷의 능력치 변화도 턴 상태에 연결되어 있습니다. 회복기와 연속기는 별도 회귀 테스트에서 실제 HP·PP·명중 횟수로 점검합니다.

역린류는 기술이 명중한 동안 강제 재사용하고 PP는 시작할 때 한 번만 차감합니다. 방어·무효로 공격이 연결되지 않거나 잠듦 등으로 행동이 끊기면 고정이 풀립니다. 철제광선은 방어에 막혀도 최대 HP의 절반을 소모하며, 피해 이벤트에 **철제광선의 반동**으로 표시합니다.

사용자 요청에 따른 **이 게임의 자체 규칙**으로 생명의구슬 HP 비용을 최대 HP의 1/8로, 역린류의 지속을 2~5턴으로 설정했습니다. 본가 및 Pokémon Showdown의 수치와 다를 수 있습니다. 테라스탈은 장착 도구로 타입이 고정됩니다.

**종 목록만 M‑C 데이터 기준입니다.** 전투 규칙은 공식 Pokémon Champions 또는 Pokémon Showdown과 같지 않습니다. 기존 혼합 모드에 메가진화, 테라스탈, Z기술, 다이맥스·거다이맥스를 함께 둡니다. 메가 **82폼**의 종족값·타입·특성 ID와 전용 스톤을 연결했고, 확인된 메가·거다이맥스 폼 이미지 정면/후면 **116쌍**을 로컬에 둡니다. 거다이맥스 전용 기술은 현재 데이터에 있는 **34폼**으로 확장했습니다. Pokémon Champions의 공식 Regulation M‑C는 메가진화를 배틀당 한 번 허용하며 다이맥스/거다이맥스는 허용 기믹으로 공지하지 않습니다. 이 프로젝트의 다이맥스·거다이맥스는 별도 혼합 모드 기능입니다.

`node scripts/audit-coverage.cjs`로 편성 목록의 특성 및 기술 연결을 확인할 수 있습니다. 현재 감사에서 로스터 고유 특성 **203개 중 202개**는 배틀 엔진 효과에 연결되어 있고, 남은 **도주**는 야생 포켓몬에게서 달아나는 효과라 현재 트레이너 대전 모드에서는 발동 대상이 없습니다. 주요 적용 항목에는 열매 발동·재사용·회수, 상태와 날씨 상호작용, 더블 배틀 아군 효과, 교체/접촉 발동, 능력치 반사·복사, 특수 폼 전환 및 무게 기반 기술 위력 계산이 포함됩니다. 미러아머·흡반·부식·탈·변환자재·리베로·변덕쟁이·배틀본드·배틀스위치·제로투히어로 등도 실제 턴 처리에 연결했습니다. 규칙 자료는 고정된 M‑C Pokémon Showdown 데이터에서 확인했으며, 이 프로젝트의 엔진은 공식 게임 시뮬레이터와 동등하지 않습니다. 효과별 세대 예외와 일부 상호작용은 계속 축약되어 있습니다.

## 그래픽과 리소스

배틀 카메라와 HUD를 분리해 지진·기믹 연출 중에도 정보창과 메뉴가 고정됩니다. 체격은 원본 신장·몸무게, 스프라이트의 실제 불투명 영역과 지면 기준점으로 맞춥니다. 긴 뱀 형태의 도감 신장은 길이로 취급해 과도한 세로 확대를 줄입니다. 작은 포켓몬도 보이도록 카메라 비율을 압축하므로 화면의 크기가 현실의 미터 비율과 일치하는 것은 아닙니다. 변신·일루전은 보이는 종의 체격을 사용합니다.

지진·역린·철제광선·파도타기·골드러시·성묘는 각각 균열·용 기운과 발톱·충전 광선·큰 물결·금빛 동전·동료의 영혼 연출을 사용합니다. 기술명 표시 → 준비 → 시전 → 피격 → HP 변화 → 부가 효과 순서를 실제 엔진 이벤트로 재생하며, HP 숫자와 바는 피격 후 같은 값 사이에서 함께 움직입니다. 교체는 회수 광선 → 볼 투척 → 등장 → 착지로 나뉩니다. 화상·독·마비·수면·얼음·혼란·헤롱헤롱·아쿠아링 아이콘은 현재 상태와 동기화됩니다. 메가진화·테라스탈·다이맥스는 입자, 카메라, 색상과 소리를 구분합니다.

기술 메뉴는 타입·분류·위력·명중·PP를 표시하고 마우스 및 키보드 선택 커서를 제공합니다. 더블 배틀에서 기술을 가리키면 단일 대상과 범위 대상에 다른 커서와 연결선이 나타나며, 지진·파도타기처럼 아군을 포함하는 기술은 아군도 표시합니다.

현재 편성 목록의 **정면 264/264, 후면 264/264** 로컬 PNG를 파일 존재·PNG 형식·실제 Chrome 디코딩으로 확인했습니다. 종별 도감 ID·폼 ID·경로·SHA256·출처를 대조한 목록은 [`outputs/regmc-asset-audit.json`](outputs/regmc-asset-audit.json)에 있습니다. 지역·크기·깃털 폼은 전국도감 번호 대신 PokeAPI의 고유 폼 ID를 사용하므로 기본형 그림을 재사용하지 않습니다. 메가 82폼과 거다이맥스 34폼의 정면/후면은 [`public/sprites/forms/manifest.json`](public/sprites/forms/manifest.json)에 따로 기록되어 있습니다. 검증되지 않은 이미지는 `unavailable.svg`와 종 이름으로 표시합니다.

기본 이미지 출처는 PMDCollab/SpriteCollab의 CC BY‑NC 4.0 팬 작품과 [PokeAPI/sprites](https://github.com/PokeAPI/sprites)의 PNG입니다. PokeAPI 저장소의 코드 라이선스가 포켓몬 그림의 재배포 권리를 뜻하지 않으며, 그림 저작권은 The Pokémon Company가 보유한다고 원본이 명시합니다. 출처·개별 저작자·파일별 경로는 [`public/sprites/attribution.json`](public/sprites/attribution.json), [`public/sprites/CREDITS.md`](public/sprites/CREDITS.md), [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md)에 기록했습니다. 공식 음악은 포함하지 않습니다.

리자몽·마기라스 기본 스프라이트는 기존 로컬 픽셀 그림의 선명도·화면 크기를 보정했습니다. 공식 본가 도트 그림으로 교체한 것은 아닙니다. 테라스탈은 타입별 색상의 크리스탈 왕관과 전장 광원 효과를 표시합니다.

## 배틀 효과음

기본 효과음은 18타입과 스텔라, 교체·기절·회복·기믹·HP 경고용 직접 제작 합성음입니다. 효과음과 BGM 음량은 따로 설정합니다. 공식 포켓몬 게임 음원은 포함하지 않습니다.

사용할 수 있는 음원 파일은 설정 → **효과음 파일 가져오기**로 연결합니다. 파일을 실제 디코딩한 뒤 IndexedDB에 저장하므로 새로고침 후에도 유지됩니다. `move-surf.wav`, `move-steelbeam.ogg`처럼 영문 기술 ID를 붙이면 그 기술에만 사용하고, `type-water.wav`는 물 타입 공통으로 사용합니다. 전용 기술 파일 → 타입 파일 → 기본 합성음 순으로 선택합니다. `switch-in.wav`, `switch-out.wav`, `faint.wav`, `low-hp.wav`, `gimmick-mega.wav`, `gimmick-tera.wav`, `gimmick-dynamax.wav`, `status-burn.wav`도 지원합니다. WAV·OGG·MP3·M4A, 파일당 최대 8MB·20초이며 실패한 파일은 정상 등록으로 세지 않습니다. **가져온 효과음 지우기**는 사용자가 가져온 브라우저 음원만 지웁니다.

`node scripts/audit-rule-fidelity.cjs`는 원본에서 생성한 510개 기술의 타입·분류·위력·명중·PP·우선도·접촉·탄환·베기·펀치 등 기본 필드를 대조하고 `outputs/rule-fidelity-audit.json`에 기록합니다. 인파이트·거대해머의 잘못된 펀치 판정과 일부 기술의 누락된 탄환·베기 판정을 수정했습니다. 생성기에서 물수리검의 실제 위력 15를 40으로 바꾸던 처리도 수정했습니다. 기본 필드 일치가 모든 고유 효과·특성 상호작용의 완전한 본가 구현을 의미하지는 않습니다. 앞서 명시한 자체 규칙과 일부 축약 판정은 남아 있습니다.

## 검사와 데이터 재생성

급소/상성 전용 효과음을 사용하려면 설정에서 `critical-hit.wav`, `super-effective.wav`, `resisted-hit.wav`라는 파일명으로 가져올 수 있습니다. 파일이 없어도 합성음이 재생됩니다.

```powershell
npm test                 # 자동 테스트
npm run build            # 타입 검사와 배포 빌드
npm run test:browser     # 실제 Chrome/Edge: 편성·싱글·더블·기술·교체·모바일
npm run test:cinematic   # 전용 기술·HP 지연·교체·기믹·대상·8개 화면 배치·실제 WAV 가져오기
npm run test:server      # 친선 서버 판정
npm run test:friend      # 실제 두 브라우저의 친선 프리뷰·선출·턴 처리
npm run test:hit-effects # 실제 브라우저의 급소+약점 팝업·섬광·HP 변화
npm run assets:check     # 현재 264개 종·폼 정면/후면 PNG 디코딩
npm run assets:regmc:audit # 로컬 PNG 해시·종 ID·경로·출처 기록 대조
npm run assets:forms     # 82개 메가 + 34개 거다이 폼 경로/파일 확인
npm run assets:metrics   # 실제 픽셀 경계와 신장 메타데이터 생성
node scripts/audit-coverage.cjs
```

소스 스냅샷은 `work/regmc/`에 고정했습니다. 이를 수정한 뒤 `npm run data:refresh`, `npm run assets:regmc`, `npm run assets:index`, `npm run assets:metrics` 순서로 새 데이터를 검증할 수 있습니다. 스프라이트 다운로드에는 네트워크와 Chrome/Edge가 필요합니다. 테스트나 빌드가 실패하면 해당 명령의 실제 오류를 기준으로 수정하세요.
